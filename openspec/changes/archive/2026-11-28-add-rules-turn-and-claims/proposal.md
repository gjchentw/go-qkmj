# Proposal

## Why

切片 1 已完成 `rules/game-model` 與 `rules/scoring`（純牌型、洗牌牆、5 組 + 1 對拆解與 69 組黃金樣本計台）。現在需要實作 `internal/rules` 第二個垂直切片：`rules/claim-arbitration`（宣告視窗與 0.95m 嚴格過水）與 `rules/turn-cycle`（單局回合摸打、自動補花、自身暗槓／加槓、搶槓與海底流局狀態機），完整建立一局內部的純函式／純狀態機驅動核心。

## What Changes

- 新增 `rules/claim-arbitration` 能力規格與純狀態機元件：
  - 三種宣告視窗：出牌後（吃／碰／明槓／胡）、加槓時（搶槓胡）、亮花後（八仙過海／七搶一）。
  - 僅私下詢問至少有一個合法選項的玩家；等待所有被詢問者回覆不可更改的決定後再仲裁。
  - 多種吃法選擇（`WaitChowChoice`）、優先順序仲裁（胡 > 槓 > 碰 > 吃）、依出牌／觸發者下家順時針優先的截胡規則（不支援一炮多響）。
  - QKMJ 0.95m 嚴格過水狀態機：放棄胡牌（含放槍、搶槓與自摸）進入過水、過水期間連自摸亦不提供、須摸到或補到一張「非花且不能胡」的牌才解除，並私下發出進入／解除通知；花牌宣告不適用過水。
  - 仲裁後僅公開最終成立結果，絕不外洩他人選項或未成立宣告。
- 新增 `rules/turn-cycle` 能力規格與純狀態機元件：
  - 完整回合狀態機：`WaitDraw` → 摸牌 → 摸到花自動補花（含補花後觸發花牌宣告視窗）→ 計算全手自身選項（自摸、暗手任意四張暗槓、既有碰牌任意第四張加槓）→ `WaitSelfDeclare` → `WaitDiscard` → 宣告視窗 → 宣告結果轉移與海底流局檢查。
  - 莊家第一手不摸牌直接進入自身選項（天胡／暗槓）。
  - 暗槓／明槓／加槓後依 QKMJ 基線進入 `WaitDraw` 等待手動補牌，並標記補牌狀態供杠上開花判定；可連續槓。
  - 可摸張數為 0 時禁止暗槓、加槓與他家吃碰槓，僅允許胡牌（海底摸月／河底撈魚），嚴格保護 16 張保留牌。
  - 接受外部注入之思考耗時（純值參數，不讀取系統時鐘），出牌時累加並公開各家思考時間。

## Capabilities

### New Capabilities

- `rules/claim-arbitration`: 定義出牌後、加槓搶槓與花牌宣告三種宣告視窗狀態機、吃法選擇、胡＞槓＞碰＞吃優先仲裁與截胡、0.95m 嚴格過水規則，以及僅公開最終結果的資訊隔離契約。
- `rules/turn-cycle`: 定義單局摸打循環狀態機：等待摸牌、摸牌與自動補花、全手自身宣告（自摸／暗槓／加槓）、等待出牌、宣告結果座位轉移、可摸張數為 0 時僅能胡與海底流局，以及注入式思考時間累計。

### Modified Capabilities

（無，不變更既有的 `architecture`、`rules/game-model` 與 `rules/scoring` 主規格。）

## Impact

- **Go 程式碼**：於純標準庫套件 `internal/rules/` 新增 `claim.go`、`turn.go`、`events.go` 與對應單元測試，維持零外部依賴、零 goroutine、零 I/O 與零系統時鐘讀取。
- **後續切片解鎖**：為切片 3（`rules/hand-lifecycle` + `rules/match-progression`）提供完整的單局內部回合與宣告狀態機核心，後續可再無縫串接 95p3+ 擴充規則（如早裁、立直、四風連和）。
